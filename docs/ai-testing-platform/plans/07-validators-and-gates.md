# 07 · 校验器与门禁

**状态：设计已定** ｜ 前置：01 资产模型

> 「AI 不裁判，框架裁判」的落地。校验器是**确定性代码**，把创建准则变成机器检查。

## 1. 校验器做什么

对**每个入库的资产**（场景/步骤/方法脚本/用例）跑规则，不过不过库。

```
生成/保存/导入
   ↓
校验器（确定性）
├─ 通过 → 入库
└─ 不过 → 结构化错误 {path, rule, msg, severity}
```

`severity=error` 拒入库；`warn` 入库但标记。

## 4. AI 生成专用校验（幻觉）

| # | 规则 | 级别 |
|---|---|---|
| A1 | 不存在的接口：`url` 不匹配知识库 api 条目 | warn |
| A2 | 不存在的字段：`json_path` 未在响应样例/文档出现 | warn |

A1-A3 软校验（人工确认），A4 硬校验。

## 5. 门禁落点（八道门）

| 门 | 位置 | 判什么 | 不通过 |
|---|---|---|---|
| 知识门 | `knowledge.ingest` | 结构化 + 溯源 + 可测 | 降级 candidate |
| 确认门 | `case.create/confirm` | `confirm_source` 有值；关联 open 疑问已收敛 | 拒绝 |
| 生成门 | `scenario.generate` | schema + 只用注册工具/方法 + 溯源 | 拒入库 |
| **校验门** | 场景/步骤/方法入库 | 第 2/3 节规则 | 拒入库 / warn |
| 执行门 | 引擎后置校验 | 机械判定 | 该步 fail |
| 保证门 | 场景 `draft → verified` | 可执行 + 可稳定通过 + 有增量价值 | 不给 verified |
| 根因门 | `bug.root_cause` | 每条结论带证据 | 标红/不入库 |
| 变更门 | 任何 update | `change_reason` 非空 + 已传导下游 | 拒绝 |

## 6. 实现形态

```
validators/
├── scenario.py      # 场景/步骤规则
├── method.py        # 方法脚本规则（AST + 白名单）
├── semantic.py      # 跨字段
├── hallucination.py # AI 生成校验
├── registry.py      # 工具/方法/校验类型/变量前缀 查询
└── errors.py
```

- 输入：资产文档或表行；输出：`{valid, issues[]}`；**纯函数、可单测**
- 同一套跑在：AI 生成后、编辑器保存后、导入后、存量回扫

## 7. 设计决策

| # | 问题 | 决策 | 理由 |
|---|---|---|---|
| 1 | 拆分阈值 | **步骤数 > 15 → warn**（可配） | 超过就该拆场景/提方法 |
| 2 | warn 是否可忽略 | **可"忽略并存"**，但需记录理由 + 记录人 | 否则告警攒成噪音；但忽略必须留痕 |
| 3 | 存量回扫 | **只扫 `active`**（draft/broken 不必扫） | 省算力，聚焦在用资产 |
| 4 | 方法脚本白名单 | 见 06 §6.3 | 单一出处，不重复定义 |
