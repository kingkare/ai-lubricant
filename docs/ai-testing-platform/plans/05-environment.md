# 05 · 环境管理

**状态：设计已定** ｜ 前置：01 资产模型

> 你指出：可以有多套环境用于不同任务，一般是**人为管理**使用的。

## 1. 定位

环境是**人为管理的独立实体**：定义"在什么目标上跑"（地址、账号、开关、密钥引用）。任务引用环境，不同任务用不同环境。

## 3. 分层继承

```
基线 (base)
  ├─ 环境组 (staging-group)
  │    ├─ staging-1
  │    └─ staging-2
  └─ 环境组 (dev-group)
       └─ dev-1
```

- 子环境**只配差异**（如 `base_url`），公共变量在父级
- 读取时**递归向上合并**（子覆盖父）
- **防循环继承**（写入时校验：父链不得出现自身）
- 合并算法见 `06-script-engine.md` 第 2.3 节

## 4. 变量类型化（重要）

| 类型 | 示例 | 意义 |
|---|---|---|
| `string` | `"https://api.x.com"` | |
| `int` | `8080` | 端口等 |
| `float` | `1.5` | 超时秒数 |
| `boolean` | `true` | 开关 |
| `json` | `{"k": "v"}` | 结构化配置 |
| `list` | `["a", "b"]` | 列表 |
| `dict` | `{...}` | 字典 |

**保持原生类型**——`{{env.port}}` 是 int 就替换成 int，否则 `port > 8000` 这类判断会错。

## 5. 密钥处理

- `is_secret=true` 的变量：
  - **读取接口脱敏**（返回 `***` 或仅末 4 位）
  - **引擎执行时服务端注入真值**
  - **日志/报告/trace 一律脱敏**
- 存储：**复用服务既有加密能力做列级加密**（`is_secret` 变量的 `value` 加密存）

## 6. 人为管理的操作

| 操作 | 说明 |
|---|---|
| 新建/复制环境 | 从基线派生，只填差异 |
| 编辑变量 | 带类型、可标密钥 |
| 切换默认环境 | |
| 归档 | 不删，标 archived |
| 权限 | 谁能改环境（密钥敏感） |

## 7. 环境与任务/场景的关系

```
任务 (task) ──引用──▶ 环境 (env)          ← 任务级指定，本次运行用哪套
场景 (scenario) ──默认──▶ 环境            ← 场景可给默认，任务可覆盖
运行 (run) ──快照──▶ 环境 + 变量           ← 运行记录环境快照，保证可复现
```

- **优先级**：任务 `env_id` > 场景 `env_id` > 无（报错）
- 运行记录**环境快照**（变量值快照，密钥除外），便于复现与审计

## 8. 设计决策

| # | 问题 | 决策 | 理由 |
|---|---|---|---|
| 1 | 变量加密方案 | **复用服务既有加密能力**做列级加密（`is_secret` 的 `value` 加密存） | 不引入新依赖；与既有凭据处理一致 |
| 2 | 环境权限模型 | **项目成员可读、管理员可改**；密钥变量**仅管理员可见真值** | 环境含密钥，写权限必须收紧 |
| 3 | 环境快照含密钥？ | **不含**，只记**引用**（`{{env.x}}` 指向变量名） | 快照可能被导出/分享，绝不含密钥 |
